# satz-studio verification

What is proven, where, and how to run it. Every automated check runs offline against
`tests/fixtures` and the pinned `vendor/satz`; the ones that drive the `satz` binary
need it installed at `MIN_SATZ` or newer. The GitHub reads — the look for a satz-studio
update, satz's installer — run against a canned server on a local port. The manual checks
that need a window or a machine are listed at the end.

## 1. What is proven where

The end-to-end tests (`crates/satz-studio-core/tests/e2e_*.rs`) take the paths the
app takes — `edit::delegated_write`, the write lock, `Snapshot::take` and
`Snapshot::delegate` around `satz_interview` over the estate's `satz mcp` with
`McpChecker`; `EditSession::apply` and `Proposed::commit`; a pack switched through
`satz_add_preset` and `satz_remove_preset` — against a
temporary estate written by `satz interview --create` over `vendor/satz`, and against
a copy of satz's smoke estate. The unit tests of each module are named where they
carry a claim the harness relies on.

## 2. The manual smoke walk

The estate views are checked by hand: [`ui.md`](ui.md), section "The smoke walk" —

## 3. Checks that need a machine

- **The client itself.** With Claude Code installed, the Agent destination's "Configure
  Claude Code" and then "Open in claude": `/mcp` in the terminal that opens lists the
  satz server, and `satz_questions` there answers for the estate the window has open.
  What the harness proves is everything up to that terminal — the run each button makes,
  the block satz writes and the refusals — and what needs a machine is the client
  reading it.
- **The editor a pack opens in.** On each OS, with Settings → Editor empty, Packs → a
  pack's Edit opens the file in the system's text editor (TextEdit on macOS, the desktop's
  handler for the file on Linux, Notepad on Windows) under its path without `..`; set the
  Editor to an installed editor's command (`zed`, `subl -n`) → Save → Edit opens it there;
  type a name nothing installs → the line under the field reads "not saved: …" in the error
  color and Save is disabled. The harness proves the command line built for each platform,
  the path and the check; what needs a machine is the editor appearing.
- **The look.** The window is the Dioxus component library's
  ([ADR 0034](adr/0034-the-window-is-built-from-the-dioxus-component-library.md)), and no
  test sees it: `dx serve --package satz-studio --hot-reload true`, then every destination
  with the smoke estate open, in the light and the dark theme (Settings → Appearance) —
  the sidebar folds to its icons from the top bar's first button and each folded entry
  names itself on hover; cards, badges, buttons and toggle groups are the library's; the
  path bar's tooltips open upward; a pack's in/out button opens what flows through it
  under its row; the drawer, the palette (⌘K) and a toast stand over the view. The
  layout of `assets/app.css` is what is judged there, since the UI components are drawn as
  the library publishes them.
- **The bundles.** `.github/workflows/release.yml` builds the `.app` and `.dmg` on
  `macos-15` (arm64 — macOS is Apple silicon alone), the `.deb` and `.AppImage` on
  `ubuntu-24.04` and the `.msi` on `windows-2022`, both x86_64. Every bundle carries
  `LICENSE`, `NOTICE`, `THIRD-PARTY-LICENSES.md` (the license text of every crate the app is built from), `LICENSE-Geist` (the typeface's), `LICENSE-dioxus-components` (the component library's) and `LICENSE-satz-tree-sitter` (the vendored grammar's) (`bundle.resources` in `crates/satz-studio/Dioxus.toml`): in
  `SatzStudio.app/Contents/Resources/`, in the MSI's install directory beside the
  executable, and in `/usr/lib/SatzStudio/` in the `.deb` and the AppImage. The macOS job
  compares the six files in the `.app` with the checkout's and fails without them,
  because dx skips a resource it cannot find with a warning and exits 0; the `.deb`, the
  AppImage and the MSI are opened by hand after a tag to see them. A local
  `dx bundle` runs from the repository root, where dx finds the six paths. That each bundle launches and opens
  the fixture estate is checked by hand on a machine of that OS: unzip or mount, start
  the app past the unsigned-build prompt the README names, the Open door → a COPY of the
  smoke estate — the scratch folder the smoke walk in `ui.md` describes, the `.satz`
  files under `yaml/` beside a `config.toml` with `yaml_dir = "yaml"`, because `satz mcp`
  opens only an estate file inside the directory holding its `config.toml`
  ([ADR 0022](adr/0022-the-mcp-root-is-the-one-satz-mcp-config-renders.md)) and
  `tests/fixtures/smoke/config.toml` points into the submodule — → Open → the top bar shows `smoke.satz`, and the window
  lands on the Overview with the estate's own facts in it and "the signed-in identity — local
  mode" in its Runs as row. On Linux the `.deb` declares the runtime libraries; the AppImage
  needs `webkit2gtk-4.1` on the host. On Windows satz
  releases `satz-x86_64-pc-windows-msvc.zip` with `satz-installer.ps1` beside it, which
  installs that build on ARM64 Windows too; with no satz, the banner's "Install satz"
  runs that installer. That run is checked by hand on a Windows machine without satz:
  the log names `satz-installer.ps1` as verified, `satz.exe` lands in
  `%USERPROFILE%\.local\bin`, the user `PATH` is unchanged, and the banner goes.

## 4. How to run everything

```sh
cargo fmt -p satz-studio-core -p satz-studio -- --check      # the two packages
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked                                # every unit and integration test (CI adds --no-fail-fast)
bash scripts/e2e.sh                                            # the satz gate, the e2e tests, a dx build of the app
bash scripts/check-names.sh                                    # the privacy gate over the tree
bash scripts/update-third-party-licenses.sh --check            # THIRD-PARTY-LICENSES.md against Cargo.lock (cargo-about 0.9.2, after cargo fetch --locked)
dx bundle --package satz-studio --platform desktop --release   # this machine's bundle, under target/dx/satz-studio/bundle/
```

`scripts/e2e.sh` checks that `satz --version` is at least `MIN_SATZ`
(`crates/satz-studio-core/src/satz/binary.rs`), runs
`cargo test -p satz-studio-core --locked --test 'e2e_*'`, and without `--ci` also
`dx build --package satz-studio --platform desktop`, the build the app runs as, which
compiles the component library's stylesheets into it; one verdict line per step, and the first failure
ends the run. `ci.yml` runs it with `--ci` after the tests in its `core` job on Linux, on
every pull request, on the push to `main` that merges it, on a release tag, by hand and
once a day on `main`. The e2e tests each write a temporary estate whose `config.toml` points into
`vendor/satz` by absolute path, so nothing under the repository is written.
